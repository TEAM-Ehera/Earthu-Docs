# 계정 관리

로그인 화면의 ‘비밀번호를 잊으셨나요?’와 마이 페이지의 ‘계정 관리’에서 사용한다. 기존 인증 쿠키와 CSRF 요청 헤더(`X-Eolssu-Request: 1`)를 사용한다.

| 메서드·경로 | 요청 | 결과 |
| --- | --- | --- |
| POST `/v1/auth/password-reset/request` | `email` | 인증된 계정에 6자리 코드 전송. 계정 존재 여부를 구분하지 않는 응답. |
| POST `/v1/auth/password-reset/confirm` | `email`, `code`, `password` | 비밀번호 변경, 코드 폐기, 전체 세션 삭제 및 현재 쿠키 삭제. 204. |
| POST `/v1/auth/logout-all` | 로그인 쿠키 | 현재 회원의 전체 세션 및 현재 쿠키 삭제. 204. |
| GET `/v1/me/account/data-policy` | 로그인 쿠키 | 삭제·익명화·유지 항목 안내. `Cache-Control: no-store`. |
| DELETE `/v1/me/account` | 로그인 쿠키, `password`, `confirmed: true` | 비밀번호 재확인 후 데이터 처리 및 탈퇴. 204. |

코드는 10분간 유효하며 오입력 5회 이후 새 코드가 필요하다. 재발송 최소 간격은 60초다. 기존 인증 요청 제한을 연결하여 IP·이메일 단위 요청 횟수도 제한한다. 새 비밀번호는 8자 이상, UTF-8 기준 72바이트 이하로 제한한다. 재설정 코드는 BCrypt 해시로만 저장한다. 동시 코드 사용은 회원 행 잠금으로 직렬화한다.

탈퇴는 하나의 DB 트랜잭션으로 처리한다. 미래의 공개 주최 모임이 있으면 409로 거절하고 먼저 모임을 취소하도록 안내한다. 비밀번호 오류는 403, 인증이 없으면 401, 동의 누락은 400이다.

- 삭제: 회원 행(이메일·비밀번호 해시·인증/재설정 정보·프로필), 전체 세션, 관심, 참여, 후기, 본인이 제출한 신고.
- 익명화/삭제 표시: 본인 댓글의 내용과 작성자 연결 제거. 답글 구조와 기존 공개 범위는 유지. 주최 모임의 주최자 이름·학교·국적 및 회원 연결 제거.
- 유지: 주최 모임의 내용·이미지, 다른 회원이 작성한 활동과 답글. 모임 주최자에 새로운 연결 없는 UUID를 사용해 기존 데모 모임(`hostId == null`) 판별과 구분한다.

모임 내용이나 이미지에 직접 입력한 개인정보는 자동 탐지·삭제하지 않는다. 업로드 파일은 기존에 소유자 메타데이터가 없으므로 탈퇴 시 파일 삭제를 수행하지 않는다. 삭제·유지 범위는 탈퇴 동의 화면에 표시한다. 별도 백업·외부 로그의 보관 및 삭제 정책은 이 애플리케이션 트랜잭션의 범위에 포함되지 않는다.

운영 DB에는 Flyway `V5__account_management.sql`로 재설정 필드와 세션 조회 인덱스를 추가한다. 로컬 H2는 기존 `ddl-auto=update`로 반영한다. 메일 발송은 기존 SMTP 설정을 사용한다.

검증: `AccountManagementTests`는 H2와 모의 SMTP를 사용하여 코드 일회성, 5회 오입력 영속화, 만료, 발송 간격, 전체 세션 해제, 타 회원 세션 보존, 탈퇴 제한, 실제 DB 데이터 삭제/익명화, HTTP 인증·CSRF·동의 검증을 확인한다. 실제 외부 SMTP 전송과 운영 PostgreSQL 배포는 별도로 확인해야 한다.
