# 계정 관리·탈퇴 데이터 처리

2026-10-03 현재 소스 구현 기준이다. 운영 배포 완료 기록과 구분한다.

## 화면과 사용 흐름

- 로그인 `/auth`의 ‘비밀번호를 잊으셨나요?’ 또는 마이 `/my`의 ‘비밀번호 재설정’에서 `/auth/reset-password`로 이동한다.
- 가입한 학교 메일로 받은 6자리 코드를 입력하고 새 비밀번호를 두 번 입력한다. 완료하면 모든 기기에서 로그아웃하고 새 비밀번호로 로그인한다.
- 마이의 ‘전체 기기 로그아웃’은 확인 후 현재 기기를 포함한 모든 세션을 폐기한다.
- 마이의 ‘회원 탈퇴·데이터 처리’에서 처리 범위를 읽고 현재 비밀번호와 명시적 동의를 제출한다. 예정된 공개 주최 모임이 있으면 먼저 취소해야 한다.

## 실제 API 계약

모든 변경 요청에 `X-Eolssu-Request: 1` 헤더가 필요하다. 로그인 API는 HttpOnly 세션·refresh 쿠키로 인증한다. JSON 필드명은 현재 구현의 camelCase를 따른다.

| 메서드·경로 | 요청·권한 | 성공 |
| --- | --- | --- |
| POST `/v1/auth/password-reset/request` | 공개, `{email}` | 200 `message`. 인증된 계정이 있는 경우 코드 발송. 계정 존재 여부는 응답으로 공개하지 않음 |
| POST `/v1/auth/password-reset/confirm` | 공개, `{email,code,password}` | 204. 비밀번호 변경·코드 폐기·전체 세션 해제·현재 쿠키 삭제 |
| POST `/v1/auth/logout-all` | 로그인 | 204. 현재 회원의 전체 세션 및 현재 쿠키 삭제 |
| GET `/v1/me/account/data-policy` | 로그인 | 200 `{data:{deleted,anonymized,retained,requirement}}`, `Cache-Control: no-store` |
| DELETE `/v1/me/account` | 로그인, `{password,confirmed:true}` | 204. 데이터 처리 및 탈퇴·현재 쿠키 삭제 |

재설정 코드는 10분간 유효하고 최대 5회 오입력 후 새 코드가 필요하다. 발송 간격은 60초이며 기존 IP·이메일 단위 요청 제한도 적용한다. 코드는 BCrypt 해시로 저장하고 회원 행 잠금으로 동시 사용을 직렬화한다. 새 비밀번호는 8자 이상, UTF-8 기준 72바이트 이하이다.

오류: 코드 오류·만료·동의 누락 등 입력 검증은 400, 인증 필요는 401, 탈퇴 비밀번호 불일치는 403, 예정된 공개 주최 모임은 409, 요청 제한은 429, 발송 또는 인증 보호 장애는 503이다. 오류는 기존 Spring Boot 기본 응답을 사용한다.

## 탈퇴 시 처리 범위

| 처리 | 항목 |
| --- | --- |
| 삭제 | 회원 행의 이메일·비밀번호 해시·학교 인증/재설정 정보·프로필, 전체 로그인 세션, 관심, 참여, 후기, 본인이 제출한 신고 |
| 내용 삭제·연결 제거 | 본인 댓글의 본문·작성자 연결. 삭제 표시하며 답글 구조와 기존 공개 범위를 유지 |
| 주최자 정보 제거 | 모임의 주최자 이름·학교·국적·기존 회원 연결. 새 연결 없는 UUID로 데모 모임과 구분 |
| 유지 | 주최 모임의 내용·이미지, 다른 회원의 활동과 답글 |

한 DB 트랜잭션으로 처리하며 탈퇴는 되돌릴 수 없다. 모임 내용·이미지에 직접 넣은 개인정보는 자동으로 탐지하거나 삭제하지 않는다. 기존 업로드에는 소유자 메타데이터가 없어 파일 삭제를 수행하지 않는다. 별도 백업·외부 로그의 보관·삭제 기간, 신고 증거의 운영 정책과 업로드 정리는 추가 합의·구현 대상이다. 이 기록은 현재 기능 동작이며 팀의 최종 개인정보 보관 정책 확정을 뜻하지 않는다.

## DB 변경과 검증

`V5__account_management.sql`은 members의 재설정 해시·만료·발송 시각·시도 횟수와 member_sessions 회원 인덱스를 추가한다. 로컬 H2는 기존 `ddl-auto=update`로 반영한다.

- `AccountManagementTests` 8개 통과: 코드 일회성·만료·오입력 횟수 영속화·발송 간격, 전체 세션 해제·타 회원 세션 보존, 탈퇴 제한, 실제 H2 데이터 삭제·익명화, HTTP 인증·CSRF·명시적 동의.
- 웹 lint·타입 검사·프로덕션 빌드 통과.
- 미검증: 실제 외부 SMTP 수신, 운영 PostgreSQL V5 마이그레이션, 운영 배포 및 실제 계정의 화면 흐름.
