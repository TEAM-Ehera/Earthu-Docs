## 역할과 가입 상태

방문자는 웹에서 모임을 탐색한다. 로그인한 미완료 계정은 학교 인증·프로필을 이어 작성한다. 학교 인증과 프로필 완료 회원이 참가·주최한다. 호스트는 event.host_id에 해당하는 일반 회원이다. 운영자는 별도로 부여한 관리자 권한을 사용한다.

Apple/Google 로그인, 메일·비밀번호 인증과 학교 메일 수신 인증은 서로 다른 단계다. 간편 로그인 메일이 개인 메일 또는 Apple 비공개 릴레이 메일이어도 학교 메일을 추가 인증해야 한다. 동일한 메일이라는 이유만으로 서로 다른 로그인 계정을 자동 병합하지 않는 설계를 제안한다.

## 필드와 검증

### 가입·프로필

이름 1~50자, 국적 국가 코드, 대학 ID, 제1언어 필수, 제2언어는 선택값 또는 명시적인 없음(null), 성별 male/female/others/none. 제1·2언어는 같은 값을 중복 선택하지 않는 것을 제안한다. 관심사는 0개 이상. UI locale은 ko/en. 국적은 필수 선택형으로 해석한다.

대학은 메일 도메인 매핑 결과를 우선한다. 매핑 실패 시 검색 선택할 수 있지만 검증되지 않은 도메인은 대학 소유 여부 확인 전 school_verified=true로 만들지 않는다. 학교 메일 변경과 대학 변경은 재인증이 필요하다. 이름·국적은 호스트 카드에 공개되는 항목이라는 안내를 프로필에서 제공한다. 성별·메일은 공개하지 않는다.

### 이벤트

제출 시 썸네일, 카테고리, 이벤트명, 시작·종료 시각, 시 코드, 지도에서 선택한 장소명·주소·좌표, 한국인 정원·외국인 정원, 모집 시작·마감, 한국어·영어 설명 필드를 받는다. 호스트 이름·대학·국적은 회원 프로필을 사용한다.

제안 제약: 이름 5~80자, 설명 각 최대 5000자, 각 그룹 정원 0 이상 정수·합계 1 이상, `recruitment_start < recruitment_end <= starts_at < ends_at`. 설명은 한/영 입력칸을 별도로 제공하며 둘 다 필수인지는 미확정이다. 계약 초안은 최소 하나 필수, 다른 언어 미작성 시 원문 표시 제안으로 둔다. 이벤트명 번역은 요구되지 않았으므로 단일 필드로 둔다.

지도에서 시 코드를 추출하고 서울특별시→서울, 인천광역시→인천, 포항시→포항으로 표시한다. 군 지역 등 시 외 지역 지원 여부는 회의 대상이다. 지도 제공자와 무관한 내부 place 식별·주소·좌표를 저장한다.

## 공개 상태와 변경

모임 등록 성공 시 `published` 상태로 즉시 공개한다. 학교 인증·필수 프로필·일정·정원 검증은 계속 적용한다. 게시 전 심사와 승인 API는 없다.

`removed`·`cancelled`는 사후 운영 상태의 설계값이며 이번에 새로 구현한 상태 전환 API는 아니다. 모집 중/마감·행사 예정/지난 표시는 날짜로 계산한다. 공개 후 수정·취소 조건과 참가자 안내는 별도 회의 항목이다.

기존 approved/submitted/reviewing 데이터는 published로 전환한다. 과거 rejected/removed/cancelled는 자동으로 다시 공개하지 않는다. 운영은 Flyway V2, local/docker는 초기 변환 컴포넌트를 사용한다.

## 썸네일·정보 패널 이미지

Spring Boot에서 인증·소유권·파일 크기·실제 형식·픽셀 수를 검사하고 카드용/상세용 처리본을 생성한다. 비공개 R2에 저장 완료된 asset ID만 이벤트 버전에 연결한다. 이미지는 DB에 바이너리로 저장하지 않고 경로·크기·상태를 관리한다.

파일 선택·업로드 중·검증 실패·ready·공개 준비·공개 완료를 구분한다. 실패 시 기존 썸네일 연결을 잃지 않게 하고 새 파일은 새 asset ID로 저장한다. 모임 등록/패널 게시 후 공개 객체 준비가 끝나야 일반 사용자에게 노출한다. 원본·미사용 자산 정리는 제출 이력 참조 여부를 확인한 뒤 수행한다. 자세한 기준은 [이미지 처리 흐름](07-tech-stack.md#비용-최소화와-이미지-저장) 및 [API](05-api-spec.md#이미지-업로드와-공개)에 있다.

## 정원·참가 정책 제안

국적 KR은 korean, 나머지는 international로 분류하는 안을 제안한다. 복수국적과 한국 국적 국제학생의 분류는 추가 결정이 필요하다. 단순 국적 그룹과 국제학생 여부를 동일 개념으로 저장하지 않는다.

신청 시 그룹을 서버에서 계산하고 participation.quota_group에 고정한다. 그룹별 confirmed 수가 그 그룹의 capacity 미만인지 같은 이벤트 잠금 안에서 검사한다. 클라이언트가 임의로 그룹을 선택하지 못한다. 국적 수정 후 기존 참가를 다른 그룹으로 자동 이동하지 않는다. 기존 참가가 있는 국적 변경 정책은 팀 결정 대상이다.

자동 확정, 호스트 정원 제외, 시작 전 취소 가능, 취소 후 재신청 가능을 계약 초안의 제안으로 둔다. 취소는 같은 참여 행을 cancelled로 바꾸고 이력을 남긴다. 삭제하지 않는다. 마지막 좌석 동시 신청과 행사 폐기를 같은 잠금 순서로 직렬화한다.

## 댓글·채팅 접근

공개 댓글은 모두 조회, 인증 회원 작성. 비공개 스레드는 작성자+호스트만 조회·답변한다. 비공개 댓글 수·본문·작성자·알림을 다른 사용자에게 노출하지 않는다. 공개/비공개 전환은 초기 범위에서 제외하는 안이다. 비공개 댓글은 웹과 앱에서 같은 스레드를 사용한다.

앱의 공지방은 호스트만 전송하고 현재 확정 참가자는 읽는다. 참여자별 호스트방은 해당 두 사람만 접근한다. 호스트는 참가자 목록에서 개별 방에 접근하며, 참여자는 다른 사람의 방 존재를 조회할 수 없다. 참가가 확정되면 개별 방을 준비하는 설계를 제안한다. 신청 전 문의는 댓글로 해결한다.

취소자는 방 접근 차단, 종료된 모임은 읽기 전용, 폐기 시 메시지 대신 폐기 사유 화면 제공을 제안한다. 신고 조사로 운영자가 열람하는 것은 일반 멤버 권한과 분리하고 감사 기록을 남긴다. 메시지 본문은 기본 푸시 내용에서 제외한다.

## 리뷰와 CTA

종료+출석 확인된 참가자에게 작성 권한을 주는 안을 제안한다. 출석 확인 방식과 마감일은 미정이다. API가 `review_action=write/view/none`과 자격 이유를 제공하여 클라이언트가 참가 버튼을 대체한다. 작성 후 보기에서 수정·삭제할 수 있다. 호스트는 참가자의 공개 리뷰를 조회한다.

사용자·이벤트별 활성 리뷰는 하나만 둔다. 삭제는 tombstone 처리하며 삭제 후 다시 작성할 수 있도록 같은 리뷰를 복원하는 안을 제안한다. 수정·삭제는 본인만, 이미 운영자가 숨긴 리뷰의 재노출은 자동 허용하지 않는다. 호스트의 리뷰 삭제 권한은 없다.

## 폐기 사유와 전달

운영자가 폐기 시 public_reason(참가자 안내), internal_reason(내부 조사)을 분리한다. 공개 사유에 신고자의 신원이나 비공개 증거를 포함하지 않는다. 이벤트명·일시·공개 사유·처리 시각은 기존 참가자와 호스트가 조회할 수 있게 남긴다.

폐기 트랜잭션에서 신규 신청 차단, 진행 예정 참가의 취소/사유 연결, 안내 대상 스냅샷과 outbox를 함께 기록한다. 완료된 출석·리뷰 이력은 무조건 취소로 덮어쓰지 않는다. 이벤트를 신청한 이력이 있는 사용자에게 조회 권한을 주는 안이며 알림 발송 대상의 범위는 확정 필요다. 푸시가 꺼져도 앱/웹 내 안내 기록은 남긴다. 웹 메일 안내 병행 여부는 추가 논의한다.

## 핵심 검증 시나리오

- 웹 생성 클릭→가입 완료 후 작성 화면 복귀, 참여 클릭→해당 상세 복귀.
- Apple/Google 로그인만 완료한 사용자는 학교 인증 없이 참가·주최할 수 없음.
- 미등록 일반 메일+대학 선택으로 학교 인증을 우회할 수 없음.
- 제2언어 없음과 성별 none을 정상 완료 값으로 수락.
- 한국인 정원 마감 시 외국인 여유 좌석으로 신청할 수 없음.
- 인증 호스트의 모임 등록 직후 공개 목록·상세에 노출되고 다른 인증 회원이 참여 가능. 승인 API 없음.
- 비공개 댓글 및 타 참여자의 1:1방을 UUID 변경으로 조회할 수 없음.
- 참여자가 공지방에 메시지를 전송하면 서버도 거부.
- 리뷰 작성→보기→수정→삭제가 동일 이벤트에서 일관되게 반영.
- 폐기된 이벤트는 탐색에서 빠지고 기존 참가자의 내 이벤트에는 사유 안내가 유지.

위 항목은 구현 후 확인할 기능 검증 시나리오이며 실행된 테스트나 출시 조건을 의미하지 않는다.
