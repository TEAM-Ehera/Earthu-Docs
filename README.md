## 업데이트 방식

1. 팀 논의·검증·개발 후속 작업은 Issue에 목적, 완료 조건, 확인 결과를 기록합니다.
2. 문서는 브랜치에서 수정하고 관련 Issue를 연결한 PR로 검토받습니다.
3. 합의가 필요한 정책은 결정 로그에 미결정으로 유지하며, 합의 후 결과와 날짜를 갱신합니다.
4. PR 병합 후 이 문서함을 팀 공유 기준으로 사용합니다. 구현 여부와 실제 사용자 검증 여부를 구분합니다.

이 저장소는 공개입니다. 비밀번호, 인증 코드, 키, 개인 정보, 서버 접속 상세는 올리지 않습니다. 운영 접속 정보는 담당자가 별도 전달합니다.
